# Does `cargo install --git <url> --rev <commit>` honour a [patch] given with --config?
# The package builder rests on it: a package is built from its own pinned commit with the tree's [patch] table applied.
# ToyOS head: ab655a1159. <scratch> is a scratch directory; <tmp> the host temp directory.
$ cargo --version
cargo 1.98.1 (797e8a9bc 2026-08-05)

## The probe: a one-file binary `probeapp` depending on crates.io `itoa = "1"`, committed in a local git repository at <scratch>/app
$ cat app/Cargo.toml
[package]
name = "probeapp"
version = "0.1.0"
edition = "2021"
[dependencies]
itoa = "1"
$ cat app/src/main.rs
fn main() { println!("{}", itoa::Buffer::new().format(7)); }
$ git -C app rev-parse HEAD
9c8f538da2673159fee22827c677204fa5bfacd6
## A replacement itoa 1.0.99 whose lib is `compile_error!`, so building it is the proof the patch applied
$ cat fake-itoa/Cargo.toml fake-itoa/src/lib.rs
[package]
name = "itoa"
version = "1.0.99"
edition = "2021"
compile_error!("the patched itoa was built");

## Arm: with --config patch
$ cargo install --git file://<scratch>/app --rev 9c8f538da2673159fee22827c677204fa5bfacd6 --root <scratch>/root --config 'patch.crates-io.itoa.path="<scratch>/fake-itoa"'
