# PR #1131 r2: what causes APST's +502 mW T14 idle (r1). T14 only, 4 energy boots, IN THIS ORDER.
# Revision 18ac97aec24c30fd8b4daed20ff7d8f91ce96a42 (nvme-apst), from <home> whose tree must be clean (the patches were for staging only).
# Every image carries probe.patch. On each I/O that arrives at an idle device, the driver asks the drive
# its power state (Get Features 02h; NVMe 2.1 §8.1.17.1: admin commands neither wake a non-operational
# state nor count as I/O for APST). Every 30 s it logs "nvme probe: ... ps<N>=<count> gap <min>..<max> ms".
# The base spec has no residency counter or transition count, so this is the state at each arrival, not a residency.
#
# Boots (all osbench_energy, the benchcase image with the energy job alone):
#   1  B            head (APST on, 100 ms bound, ITPT 50x)                  -- B before A: the drift test
#   2  A            control-no-apst.patch (no Set Features 0Ch, as main)
#   3  B-no-ps4     no-ps4.patch: EXIT_BOUND_US 5 ms, so PS4 (1+5 ms) is excluded and PS3 (1+1 ms) stays
#   4  B-itpt-x10   itpt-x10.patch: IDLE_PER_LATENCY 500, so 0..2->3 after 1 s and 3->4 after 3 s
#
# DECISION RULE, fixed before the run. x_k is boot k's energy.idle.package p50 (mW). gap = x1 - x2.
# r1 reference: A 6442-6632, B 6855-7494.
# D. Drift or order. If gap < 200 mW, B-first erased r1's increase: order or drift explains r1, and APST has
#    no resolved idle cost. The variants are then moot, and the next step is the 3+3 alternating A/B of next-latency-rule.md.
#    If gap >= 200 mW, drift is excluded and APST costs idle power.
# V. Only with drift excluded. For each variant v, f_v = (x_v - x2) / gap:
#    f <= 1/3 means v REMOVES the increase; f >= 2/3 means it KEEPS it; anything between is inconclusive (repeat that boot once).
#    - no-ps4 removes and itpt keeps: PS4 itself (its entry/exit, or the link state it brings) is the cost.
#    - itpt removes and no-ps4 keeps: the transition cadence is the cost (cycling every few hundred ms).
#    - both remove: frequent cycling into PS4. The probe's states and gaps decide which.
#    - neither removes: APST being on at all (PS3 too) is the cost, on a package the display holds in PC2. Next: the link/LTR registers.
# P. The probe line is evidence for each reading. It shows which state the drive was in when I/O arrived, and how often
#    I/O arrives during idle (the log's own writes). A variant claimed to "remove" while its probe still shows PS4 arrivals
#    (or the reverse) is reported as contradicting the reading.
# Any fix this suggests gets its own A/B under next-latency-rule.md. The AMD gets nothing new unless the fix changes its path.
#
