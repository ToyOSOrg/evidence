# One image config (benchcase, shipping kernel); jobs osbench_copyat, osbench_ipc, osbench_mem.
# Boots on the AMD: base, head, head, base (two pairs). Give each its own readback dir.
# The T14 is not booted: since round 5's head its copies of 4 KiB or more take the same path (the cap's
# ERMS condition was already true there), and shorter ones are main's again, so round 5's T14 rows stand.
#
# Rule. Mean of the two p50s per arm; "d0" is that arm's copyat.<size>.libc.s0.d0; every bound at
# 8 KiB allows +10 ns.
#  D1 premise: base copyat.8192.libc.s0.d16 and .s16.d16 >= 5 x base d0. If it fails, the stall is gone
#     from main and #1133 claims nothing: it is closed.
#  D2 short copies: head copyat.8192.libc rows at d 16..384, both source offsets, <= 1.3 x head d0.
#  D3 untouched: head copyat.8192.libc rows at d 0 and >= 512, and every mem.memcpy.* row, within
#     1.1 x base's same row.
#  D4 heap: head copyat.8192.heap <= 1.5 x head 8192 d0.
#  D5 every size: head copyat.<size>.libc.s0.d16 and .d256 for 64 KiB, 256 KiB and 1 MiB <= 1.1 x base's
#     same row and <= 1.1 x base's d0 of that size; for 4 MiB and 64 MiB (rep movsb on both arms)
#     within 1.1 x base's same row. This is round 5's 4 MiB d256 failure answered by the cap.
#  D6 IPC: ipc.reqrep.4096 and .65536 head <= 1.05 x base; a failure in one pair only is reported.
# #1133 goes for review when D1-D6 hold. The AMD stall above 1 MiB stays as recorded in the issue.
# Not judged, reported: copyat.{256,1024,2048}.libc.s0.d16 against d0 on base (does a short copy stall
# below the threshold?), and copyat.262144.libc.s0.d0 head against base (round 7's 256 KiB gap, seen there
# at 1.05 as well as mem.memcpy.262144's 0.906).
