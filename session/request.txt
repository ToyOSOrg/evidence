# Each ToyOS invocation is `cargo <words>` from a check tree at ad5db5a65. Nothing here has touched a machine.
# Image and binary hashes: <scratch>/logs/sha256.txt
#
# RULE, set before the runs (tests/guest/osbench/README.md's): a run's value is its p50; a row resolves when the exact
# two-sided Mann-Whitney test over the runs gives p < 0.05. Three boots a side cannot reach that (least p 2/20), nor
# three against four (2/35); FOUR ToyOS boots against FIVE Linux runs can (2/126), the 2026-10-28 scoreboard's shape.
# So each bench's main chain is L1 T1 L2 T2 L3 T3 L4 T4 L5. If a boot must be dropped, three boots against five Linux
# runs still resolve (2/56); fewer do not. A row left unresolved with medians more than 1.10 apart is reported as
# needing more runs, not as parity.
#
# BENCH ALONE: every boot and every Linux run below is a timing run. Each bench runs nothing else from its L1 to its
# last run (no other agent's boot between them, no build on the bench's Linux, on AC, no stick change mid-chain).
# The two benches' main chains may run in parallel with each other. The T14's LAN chain needs BOTH benches: the AMD
# bench in its Linux running only the peer, so it comes after the AMD bench's own chain has ended.
# A boot or Linux run aborted by a host network drop is rerun in place, keeping the interleaving.
#
# A ToyOS main run counts once its readback passes the row; I judge offline from the readbacks (no machine touched):
#   cargo test --test toyos-build -- --metal --metal-readback <dir> [--metal-host <amd>] osbench
# A boot that formatted DATA is refused by the judge and is repeated.
